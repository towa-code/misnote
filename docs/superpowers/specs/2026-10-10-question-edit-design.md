# 問題の編集・削除 設計

**日付：** 2026-10-10
**元になった機能案：** [docs/newfunction/question-edit.md](../../newfunction/question-edit.md)

## 背景

科目・単元管理で、問題が残っている科目や単元を削除すると 409 になり、画面には「先に問題を移動または削除してください」と出ていた。ところがフロントエンドには問題を更新・削除する画面がなく、案内された操作ができなかった。さらに、問題がなく単元だけが残っている科目でも同じメッセージが出ており、実際の原因と合っていなかった。

API（`PUT` / `DELETE /v1/questions/{id}`）はすでにあるので、足りないのは画面だけ。

## 範囲

1. 問題の編集ページ（科目・単元・問題文・正解の4項目と、削除、状態の切り替え）
2. 苦手問題一覧に、行ごとの「編集」と、科目での絞り込み
3. 科目・単元管理で、409 のメッセージを原因ごとに出し分け、問題の一覧へのリンクを付ける
4. 「克服済みにする」ボタンの文言を「もう完璧！」に変える（復習画面も揃える）

API と DB の変更はない。

## 1. 問題の編集ページ `/questions/[id]/edit`

- `[id]` は**問題の id**。復習画面 `/review/[id]` は間違いノートの id なので、そこが違う。
- `app/questions/[id]/edit/page.tsx` は `?subject=` をサーバー側で読み、`components/question-edit/question-edit-form.tsx` に渡すだけ（`/register?draft=` と同じ形）。
- 登録フォームの編集モードにはせず、4項目だけの小さなフォームを別に作った。登録フォームと共有する `RequiredBadge` / `SelectWrapper` は `components/form/field-parts.tsx`、`sectionHeading` は `lib/form-styles.ts` に移した。
- 読み込み：`GET /v1/questions/{id}` と `GET /v1/subjects`。単元は、選んでいる科目に応じて取得する。404 のときは「問題が見つかりません」と表示し、一覧に戻るリンクを出す。
- 保存：`PUT /v1/questions/{id}`。全置換なので、空にした単元・正解は `null` で送って消す。未変更のあいだは「保存する」を押せない。
- 削除：保存ボタンから離した「この問題を削除」。`window.confirm` で「間違いノートと解答履歴も一緒に削除されます」と伝えてから `DELETE`。
- 状態：フォームの下に「状態」欄を置き、「もう完璧！」（苦手中のとき）か「やっぱり苦手」（克服済みのとき）を押すと、その場で `PUT /v1/mistake-notes/{id}/status` を呼ぶ。間違いノートは、問題の `mistake_note_id` から `GET /v1/mistake-notes/{id}` で取る。フォームに未保存の変更があるあいだは押せなくし、「先に変更を保存してください」と添える（書きかけの内容を失わないため）。
- 戻り先：保存・削除・状態変更のあとは苦手問題一覧へ戻る。`?subject=` 付きで来たときは、その絞り込みに戻る。「苦手中」と「克服済み」のどちらのタブを開いていたかは引き継がない。

## 2. 苦手問題一覧

- 行のボタンは、苦手中が［編集］［復習する］、克服済みが［編集］だけ。「克服済みにする」と「苦手に戻す」は編集ページの状態欄へ移した（行のボタンを減らすため）。克服済みにするのは、復習画面からも引き続きできる。
- 科目の絞り込みはドロップダウンにした（科目はユーザーごとに増えるので、タグのようなチップにしない）。選択肢は `GET /v1/subjects` の全科目から作る。全部移し終えた科目でも、選んだまま「0件」を見せられるようにするため。
- 絞り込みは読み込み済みの一覧をフロントエンドで絞るだけ。両方のタブにかかり、タブを切り替えても解除しない。タブの件数も絞り込み後の数にする（克服済み側に残っているかが見えるように）。科目を変えたらタグの絞り込みは解除する。
- 初期値は `?subject=` から読む（`app/mistakes/page.tsx` がサーバー側で読む）。ドロップダウンを操作しても URL は書き換えない。
- 絞り込んだ科目が両タブとも0件なら「この科目の問題はありません。」と「科目・単元管理へ」のリンクを出す。

## 3. 科目・単元管理の 409

`subjects-manager.tsx` は全科目の単元を最初に読み込んでいる（`unitsBySubject`）ので、API を変えずに原因を見分けられる。

| 削除対象 | 条件 | メッセージ | リンク |
|---|---|---|---|
| 科目 | 単元が1つ以上ある | 先に単元を削除してください。 | なし |
| 科目 | 単元が0個 | この科目には問題が登録されているため削除できません。 | この科目の問題を見る → `/mistakes?subject=<科目id>` |
| 単元 | — | この単元には問題が登録されているため削除できません。 | この科目の問題を見る → `/mistakes?subject=<親の科目id>` |

単元と問題の両方が残っているときは、まず単元のほうを伝える。単元を消してからもう一度削除すると、問題のほうが出る。

## 4. 文言

| 場所 | 変更前 | 変更後 |
|---|---|---|
| 克服済みにするボタン（編集ページ・復習画面） | 克服済みにする | もう完璧！ |
| 戻すボタン（編集ページ） | 苦手に戻す | やっぱり苦手 |
| 復習画面の3連続正解の提案 | 克服済みにしますか？ | もう完璧かも？ |

タブ名「克服済み」・集計カード・克服率・エラー文は変えない（押した問題が移る先の名前なので）。「完璧！」だけだと「今回は正解した」と読まれやすいので、「もう」を付けている。

## やらないこと

- 復習画面から編集ページへの入口
- 戻り先にタブの状態を引き継ぐこと
- 単元での絞り込み
- 間違いノートが無い問題への対応。memo が必須になる前（commit d9d14c4 より前）に登録した問題には間違いノートが無い可能性があり、苦手問題一覧に出ないので編集ページにも入れない
- 一覧の取得が最大100件（API の既定値）までという既存の制限

## テストと検証

フロントエンドにはテストの仕組みがないので、`npm run lint` と `npm run build` に加えて、使い捨てのアカウントで実際に画面を操作して確認した。

- 科目・単元の削除で、3種類の 409 メッセージとリンク先が表のとおりになる
- リンクから `/mistakes?subject=` に移ると、科目が選ばれ、タブの件数が絞り込み後の数になる
- 編集ページで科目・単元・正解を変えて保存すると、絞り込みに戻り、0件の表示が出る。API で見ても変更が反映されている
- 未保存の変更があるあいだは、状態のボタンが押せない
- 「もう完璧！」で克服済みになり、克服済みタブの行は［編集］だけになる。「やっぱり苦手」で戻る
- 削除すると、問題が 404 になる。空になった科目は削除できる
- 存在しない id では「問題が見つかりません」が出る
