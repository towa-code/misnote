# 配色刷新（青ベース）設計

- 日付: 2026-08-09
- 対象: `frontend/src/app/globals.css` のカラートークン全体、および `docs/design/screens/common-ui.md`
- モックアップ: `docs/design/mockups/01_home_blue.html`（`01_home.html` を複製して配色だけ差し替えたもの）

## 背景

現行パレットを調査したところ、宣言されている16トークンが**すべて Tailwind の標準 swatch そのまま**だった。

| トークン | 値 | 実体 |
|---|---|---|
| `navy` / `navy-md` / `navy-lt` | `#1E293B` / `#334155` / `#F1F5F9` | slate-800 / 700 / 100 |
| `amber` / `-dk` / `-br` / `-lt` / `-md` | `#B45309` / `#92400E` / `#D97706` / `#FFFBEB` / `#FDE68A` | amber-700 / 800 / 600 / 50 / 200 |
| `red` / `green` / `green-lt` | `#B91C1C` / `#065F46` / `#ECFDF5` | red-700 / emerald-800 / 50 |
| `border` / `bg` / `surface` / `text` / `muted` | `#E2E8F0` / `#FAFAFA` / `#FFFFFF` / `#0F172A` / `#64748B` | slate-200 / neutral-50 / white / slate-900 / slate-500 |

`slate` を `navy` と呼び替えたことで独自体系に見えるが、実際には1つも手が入っていない。加えて4つの構造的な問題があった。

1. **`amber` が3役を兼務していた** — ブランド（ロゴ・アクティブnav・克服率バー）、主要CTA（登録ボタン・認証の送信ボタン）、警告（遅延行・遅延バッジ・フォームエラー）。押してほしいものと「遅れています」が同色で、警告としての信号強度が出ない。
2. **遅延行が行ごと沈んでいた** — `review-item.tsx` / `mistake-row.tsx` は遅延時に背景も問題文も amber にしていた。間違いノートは元々ネガティブな記録の集積なので、UI まで責める側に回ると開くのが億劫になる。
3. **褒める色が一番弱かった** — `green` (#065F46) は暗く低彩度、`red` (#B91C1C) は明るく高彩度。「正解」「不正解」ボタンを並べると不正解のほうが視覚的に強い。唯一の報酬体験が配色上いちばん地味だった。
4. **トークン外の色が散っていた** — `#CBD5E1` が13箇所ハードコード、`#E8EEF7`（Tailwind にすら無い）が1箇所、`#FFF3CC` が2箇所。`--color-amber-md` は宣言のみで使用箇所ゼロ。

なお、アクセシビリティは元から良好だった（`amber` は白地 5.05:1、`amber-lt` 上 4.86:1、色だけで意味を伝えず必ずアイコンかテキストを併記）。**この水準は落とさないことを前提条件とする。**

## 決定事項

### 新パレット

| 役割 | トークン | hex | コントラスト |
|---|---|---|---|
| サイドバー・見出し罫 | `--ink` | `#13294B` | — |
| ラベル・副見出し | `--ink-md` | `#33517E` | 白地 8.0:1 |
| ホバー地 | `--ink-lt` | `#EDF2F9` | — |
| **未克服・主要アクション** | `--primary` | `#1668C4` | 白地 **5.5:1** |
| そのホバー | `--primary-dk` | `#114F98` | 白地 7.6:1 |
| ink 上のアクセント専用 | `--primary-br` | `#4FA3F7` | ink 上 5.5:1 / **白地 2.6:1 なので白地では使用禁止** |
| 淡い青の面 | `--primary-lt` | `#EAF3FE` | — |
| **復習が遅れている** | `--late` | `#E0A32E` | ink 文字で **6.5:1** / **白文字では使用禁止（2.2:1）** |
| 遅延行の地 | `--late-lt` | `#FFF6E0` | ink 文字 13.5:1 |
| **間違い・不正解** | `--red` | `#C0242A` | 白地 5.9:1 |
| **克服済み・正解** | `--green` | `#0A7A5A` | 白地 5.3:1 |
| 克服系の淡い面 | `--green-lt` | `#E7F7F1` | — |
| ink 上の克服色専用 | `--mint` | `#3FD6A8` | ink 上 — / 白地では使用禁止 |
| 地 | `--bg` | `#F5F8FC` | — |
| 面 | `--surface` | `#FFFFFF` | — |
| 罫（通常 / 強） | `--border` / `--line` | `#DCE4EF` / `#B9C6D9` | — |
| 文字（本文 / 補助） | `--text` / `--muted` | `#0E1E33` / `#5B6B85` | muted は白地 **5.4:1**（旧 4.76:1 から改善） |

「明るさ」は2箇所で出す。`--primary` の彩度そのものと、地を無彩色 `#FAFAFA` からごく淡い青 `#F5F8FC` に振ること。白い面が地から浮くため画面全体が一段軽くなる。

### 色の語彙 — 意味は4つだけ

| 色 | 意味 | 出現箇所 |
|---|---|---|
| 青 | **未克服 / 行動** | Today・苦手問題の数字、主要ボタン、フォーカスリング、克服率バーの溝 |
| 緑・ミント | **克服済み / 正解** | 克服済みの数字、正解ボタン、克服率バーの伸びた部分 |
| 金 | **復習が遅れている** | 遅延行の地・左帯・バッジ（ここ以外に出さない） |
| 赤 | **間違えた回数 / 不正解** | 「×N回間違い」、不正解ボタン |

白地用と ink 上用でトーンが分かれる色があるが（`--primary` / `--primary-br`、`--green` / `--mint`）、意味は増えない。**同じ意味の明度違いであって、別の色ではない。**

### 適用ルール

- **金は白地の文字色に使わない。** 明るいぶん白地との対比が 2.2:1 しかない（白文字を金地に載せる場合も同じ）。金を使うのは「地・帯・バッジの塗り」だけで、その上の文字は `--ink` を載せる。
- **`--primary-br` と `--mint` は ink 面の上でのみ使う。** 白地では AA を満たさない。既存の `common-ui.md` にある `--amber-br` の同種のルールを引き継ぐ。
- **遅延は「地＋左帯＋バッジ」の3点で示し、問題文の色は変えない。** 行ごと沈ませない（背景の問題2への対応）。
- 色だけで意味を伝えない既存ルールは維持する。遅延バッジはアイコン＋「N日遅れ」のテキストを伴う。

### サマリー3セルの配色

`Today` `苦手問題` `克服済み` の3セルは対等ではない。実データ上、

- `苦手問題`（active）＋ `克服済み`（mastered）＝ 克服率の母数
- `Today` は `苦手問題` の部分集合（今日ぶんの抜き出し）

したがって色は **青＝未克服 / 緑＝克服済み** の2極のみ。`Today` と `苦手問題` が同じ青なのは同じ集合だからであって、衝突ではない。

上罫の3pxラインは廃止する。数字の色と同じ情報を二重に持つうえ、色を持たないセルに「透明な3px罫」を敷くごまかしが必要になっていた。

### 克服率バー

伸びた部分＝ミント（克服済み）、溝＝青（未克服）とする。バーの青と緑がサマリーの青と緑と同じ意味になり、20問の内訳がバーの見た目そのものになる。

検討過程で「青→ミントのグラデーション」案を採ったが破棄した。バーの伸びた部分は克服済みの分量のみを表しており、その内部で色が変わることに対応する情報が無い。装飾を情報と偽ることになるため採用しない。

## 実装スコープ

### 対象

1. `frontend/src/app/globals.css` の `@theme` ブロックを新トークンに差し替え。旧トークン名（`navy` / `amber` 系）を参照している箇所をすべて追随させる。
2. ハードコードされた色の解消 — `#CBD5E1`（13箇所）→ `--line`、`#E8EEF7`（1箇所）、`#FFF3CC`（2箇所）。未使用の `--color-amber-md` は削除。
3. 遅延表現の変更 — `review-item.tsx` と `mistake-row.tsx` の「問題文を amber にする」処理を外し、左帯を追加。
4. サマリーカード（`summary-cards.tsx`）の上罫廃止と数字の色の割り当て直し。
5. 克服率バー（`mastery-progress.tsx`）の溝と伸びた部分の色。
6. `docs/design/screens/common-ui.md` のカラートークン節を新しい値と使用禁止ルールに更新。
7. 残りのモックアップ（`02`〜`06`, `00_prototype.html`）への反映。

### 対象外

- **原因タグ6種の色分け** — 調査中に見つけた別件（現状は6種すべて `bg-navy-lt` の単色で、傾向がスキャンできない）。配色刷新とは独立に検討する。
- **ダークモード** — 現在 `body` に `#FAFAFA` 直書き、`prefers-color-scheme` の記述なし。新パレットは ink 面を持つぶん移行しやすくなるが、今回のスコープには入れない。
- **`問（active）` の文言** — モックアップに DB のステータス値がそのまま出ている（React 実装側は「復習中の問題」）。配色の問題ではないため別途。

## 検証

- 本文用の色はすべて WCAG AA（4.5:1）以上を実測で確認済み。上表のコントラスト欄がその値。
- `01_home_blue.html` をローカルサーバで表示し、`01_home.html` と並べてスクリーンショットで確認済み。遅延バッジ（金地＋ink文字）と克服率バーは拡大して可読性を個別に確認した。
- 実装後は各画面で同様に旧モックアップとの比較を行う。
