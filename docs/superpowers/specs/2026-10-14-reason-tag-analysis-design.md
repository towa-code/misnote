# 設計：教科別の間違い原因タグ分析

- 日付: 2026-10-14
- 関連: [機能案：統計ダッシュボード](../../newfunction/stats-dashboard.md)（の「間違いの原因内訳」の切り出し）・[原因タグ](./2026-08-03-reason-tags-design.md)

---

## 目的

理系の問題演習に寄せていく方針の第一歩として、原因タグ（`reason_tag`）から「自分がどう間違えがちか」を教科別に見せる。画面は**気づかせるための表示だけ**で、一覧の絞り込みなど復習への導線は持たない。

LLM は使わない（費用がかかるため）。分析文はルールとしきい値で作る。

---

## 決めたこと

- **画面:** 新規ページ `/stats`。ナビに「分析」を追加（苦手問題の次）
- **集計対象:** 克服済みも含めた全ノート。1ノート＝1票（`wrong_count` で重み付けしない。タグはノートに1つで、間違えるたびに付くものではないため）
- **タグ未設定:** 集計に入れず、件数だけ注記する。タグは任意のまま（必須にすると「とりあえずその他」が増え、null より分析を汚すため）
- **可視化:** 教科ごとの100%積み上げ横棒（先頭に全体）。円グラフは教科間の比較に向かないので使わない。依存は増やさず div で描く
- **集計の分担:** API は件数だけ返し、割合・分析文はフロント（`/stats/summary` と同じ方針。日本語ラベルも `reason-tags.ts` にだけ置く）

---

## API

`GET /v1/stats/reason-tags` → `{ rows: [...] }`。教科 × 単元 × タグごとに `note_count` / `mastered_count` / `wrong_count_sum`。詳細は [API仕様](../../design/api/stats.md)。

1本の `GROUP BY`（`mistake_notes` ⋈ `questions` ⋈ `subjects`、`units` は外部結合）。新テーブル・マイグレーションなし。

---

## 分析文

`frontend/src/lib/reason-tag-insights.ts` の純関数 `aggregate()` → `buildInsights()`。どの文も**「事実」＋「次にどうするか」**の2段で、観察だけで終わらせない。

| # | 観点 | 出す条件 | アドバイス |
|---|---|---|---|
| ① | 全体で最多のタグ | 常に（先頭） | タグごとの対策文 |
| ② | 教科の偏り（教科ごとに差が最大のタグ1つ） | 教科のタグ付き5件以上・全体より+15pt以上 | 「{教科}を解くときは特に、」＋タグの対策文。①と同じタグなら「一番上の対策を、{教科}では特に意識しましょう。」 |
| ③ | 単元への集中 | 教科×タグが3件以上・1単元が5割以上 | タグ別・単元名入りの対策文 |
| ④ | 克服率の差（最高と最低のタグ） | 各5件以上・差30pt以上 | 間隔をあけて何度か解き直す |
| ⑤ | 繰り返し（1問あたり平均間違い回数） | 3件以上・平均2回以上 | 前回のメモを読み返してから解く |

- タグ付きノートが5件未満なら分析文は出さず、棒グラフだけ見せる
- ②〜⑤は「しきい値に対する倍率」をスコアにして降順に並べ、①と合わせて最大5件。同じ種類は2件まで
- 同数タイは `REASON_TAGS` の並び（解く過程の順）で先のタグ
- しきい値と文言はファイル先頭にまとめ、使いながら調整する

---

## 色

タグごとに固定色（件数の順位で変えない）。5色は dataviz の検証スクリプトで色覚多様性の判別を確認済み、「その他」は灰色。白地とのコントラストが 3:1 を切る色があるので、ホバー／フォーカス時の件数表示・`aria-label`・「表で見る」の表で数値を文字でも出す。
