# misnote デザインガイド

misnote の見た目を決めている言語 — 色・文字・かたち・余白 — をまとめたもの。新しい画面や
コンポーネントを作るときは、まずここを見る。

**このドキュメントの位置づけ**

| | 役割 |
|---|---|
| `frontend/src/app/globals.css` の `@theme` | **実装上の正。** トークンの実値はここにしか無い |
| このドキュメント | **現在の視覚言語。** 値とその使い分けの根拠 |
| [`specs/2026-08-09-color-palette-design.md`](./superpowers/specs/2026-08-09-color-palette-design.md) | 決定の記録。なぜ旧パレットを捨てたか |
| [`design/screens/common-ui.md`](./design/screens/common-ui.md) | 挙動のルール（インタラクション・レスポンシブ） |

見た目の参照に使えるモックアップは [`design/mockups/01_home_blue.html`](./design/mockups/01_home_blue.html) **だけ**。
他のモックアップは旧配色のまま残っている実装前の資料なので、配色の参照には使わない。

---

## 1. 基本方針

misnote が扱うのは「間違えた問題の記録」で、開くたびに自分の失敗が並ぶ画面になる。
だからUIまで責める側に回らないことを最優先にする。ここから3つの原則が出る。

- **落ち着いた青を地にする。** 警告色を主役にしない。目に入る面積が最も大きい色は、
  行動を促す青か、無彩色に近い地の色であるべき
- **褒める色を弱くしない。** 「正解」「克服済み」はこのアプリで唯一の報酬体験なので、
  「不正解」より視覚的に弱くなってはいけない
- **遅れは知らせるが、責めない。** 復習が遅れている項目は地・帯・バッジで示し、
  問題文そのものの色は変えない。行ごと沈ませない

## 2. 色

### トークン

実値は `globals.css` の `@theme`。コントラスト比は実測値。

| 役割 | トークン | hex | コントラスト |
|---|---|---|---|
| サイドバー・見出し罫 | `--ink` | `#13294B` | — |
| ラベル・副見出し | `--ink-md` | `#33517E` | 白地 8.0:1 |
| ホバー地 | `--ink-lt` | `#EDF2F9` | — |
| **未克服・主要アクション** | `--primary` | `#1668C4` | 白地 **5.5:1** |
| そのホバー | `--primary-dk` | `#114F98` | 白地 7.6:1 |
| ink 面上のアクセント専用 | `--primary-br` | `#4FA3F7` | ink 上 5.5:1 / 白地 2.6:1 |
| 淡い青の面 | `--primary-lt` | `#EAF3FE` | — |
| **復習が遅れている** | `--late` | `#E0A32E` | ink 文字で **6.5:1** / 白文字 2.2:1 |
| 遅延行の地 | `--late-lt` | `#FFF6E0` | ink 文字 13.5:1 |
| 遅延行のホバー地 | `--late-md` | `#FBEDCE` | ink 文字 12.4:1 |
| **間違い・不正解・エラー** | `--red` | `#C0242A` | 白地 5.9:1 / 白文字 5.9:1 |
| その淡い面 | `--red-lt` | `#FCEBEA` | ink 文字 13.2:1 |
| **克服済み・正解** | `--green` | `#0A7A5A` | 白地 5.3:1 |
| その淡い面 | `--green-lt` | `#E7F7F1` | — |
| ink 面上の克服色専用 | `--mint` | `#3FD6A8` | ink 上のみ |
| 地 | `--bg` | `#F5F8FC` | — |
| 面 | `--surface` | `#FFFFFF` | — |
| 罫（通常 / 強） | `--border` / `--line` | `#DCE4EF` / `#B9C6D9` | — |
| 文字（本文 / 補助） | `--text` / `--muted` | `#0E1E33` / `#5B6B85` | muted は白地 **5.4:1** |

地を無彩色ではなくごく淡い青（`#F5F8FC`）にしてあるのは、白い面が地から浮いて
画面全体が一段軽くなるため。

### 色の意味は4つだけ

| 色 | 意味 | 出現箇所 |
|---|---|---|
| 青 | **未克服 / 行動** | Today・苦手問題の数字、主要ボタン、フォーカスリング、克服率バーの溝、復習日が未設定の表示 |
| 緑・ミント | **克服済み / 正解** | 克服済みの数字、正解ボタン、克服率バーの伸びた部分 |
| 金 | **復習が遅れている** | 遅延行の地・左帯・バッジ（ここ以外に出さない） |
| 赤 | **間違えた回数 / 不正解 / エラー** | 「×N回間違い」、不正解ボタン、復習のメモ更新パネル、フォームとAPIのエラー表示 |

白地用と ink 面上用でトーンが分かれる色があるが（`--primary` と `--primary-br`、
`--green` と `--mint`）、**同じ意味の明度違いであって別の色ではない。** 意味は増えない。

新しい色を足したくなったら、まず既存の4つのどれに当てはまるかを考える。
当てはまらないなら、それは本当に新しい意味なのかを疑う。

### 適用ルール

- **金は文字色に使わない。** 白地との対比が 2.2:1 しかなく、金地に白文字を載せる場合も同じ。
  金は「地・帯・バッジの塗り」だけに使い、その上の文字は `--ink` を載せる
- **`--primary-br` と `--mint` は ink 面の上でのみ使う。** 白地では WCAG AA を満たさない
- **遅延は「地＋左帯＋バッジ」の3点で示す。** 問題文の色は変えない
- **エラーは赤に統一する。** 金をエラーに使わないのは、金を「遅れ」専用に保つため
- **色だけで意味を伝えない。** 必ずアイコンかテキストを併記する（例: 間違い回数は「×」＋赤、
  遅延バッジはアイコン＋「N日遅れ」）

## 3. タイポグラフィ

### 和文2書体の使い分け

これが misnote の見た目で一番効いている選択。`app/layout.tsx` で両方を読み込み、
next/font が出す `--font-noto-sans` / `--font-noto-serif` を、`@theme` で
`--font-sans` / `--font-serif` に割り当てている（これが `font-sans` / `font-serif` クラスになる）。

| 書体 | Tailwind | 使いどころ |
|---|---|---|
| **Noto Serif JP**（明朝） | `font-serif` | 画面タイトル、セクション見出し、ロゴ、サマリーの数値、**問題文** |
| **Noto Sans JP**（ゴシック） | `font-sans`（既定） | 本文、ラベル、ボタン、メタ情報、フォーム |

問題文を明朝にしているのは、参考書や問題集の紙面に寄せて「読むもの」として見せるため。
UIの部品はゴシックのままにして、読む対象と操作する対象を書体で分けている。

### サイズ階層

`body` の基準は16px。個別の指定は `text-[Npx]` で行う。

**明朝（見出し・数値）**

| px | 用途 |
|---|---|
| 32 | サマリーカードの数値 |
| 28 | 認証画面のロゴ |
| 26 | ホーム・苦手問題一覧の画面タイトル |
| 23 | サイドバーのロゴ |
| 20 | その他の画面タイトル（登録・科目管理・復習・アカウント・クイック保存） |
| 19 / 18 / 17 | カード見出し、空状態の見出し、モーダル見出し、問題文 |
| 16 | 復習リストのセクション見出し |

**ゴシック（本文・UI）**

| px | 用途 | 使用箇所数 |
|---|---|---|
| 15 | 強めの本文、主要ボタン | 13 |
| 14 | 本文、フォーム入力欄 | 13 |
| 13 | 本文の既定 | 34（最多） |
| 12 | フォームラベル、補助テキスト | 33 |
| 11 | メタ情報のラベル | 22 |
| 10 | 最小のバッジ | 4 |

### 太さと字間

- **太さは実質2択。** `font-bold`（79箇所）と `font-medium`（6箇所）だけを使う。
  `semibold` と `normal` は使用実績がない。既定の太さのまま置くか、太くするかの二択にする
- **明朝には `tracking-[0.02em]` を添える。** ロゴだけ `0.05em` とやや広い
- **メタラベルは決まった型がある。**
  `text-[11px] font-bold text-muted tracking-[0.07em]〜[0.08em] uppercase` の組み合わせで、
  「今日の復習」「科目」などの小見出しに一貫して使う。新しいメタラベルもこの型に合わせる

> **入力欄は16px以上にする。** iOS Safari は16px未満の入力欄にフォーカスすると自動でズームし、
> レイアウトが崩れる。**現在の実装は `lib/form-styles.ts` の `inputBase` が `text-[14px]` で
> このルールを満たしていない。** 別途修正が必要な既知の不整合。

## 4. かたち

### 角丸

| Tailwind | 実値 | 用途 |
|---|---|---|
| `rounded-md` | 6px | **既定。** ボタン、入力欄、小さめの面（51箇所） |
| `rounded-lg` | 8px | カード、パネル、モーダルなど面の大きいもの（15箇所） |
| `rounded-full` | — | バッジ、ピル型のタグ（5箇所） |

迷ったら `rounded-md`。`rounded-lg` は「独立した面」に見せたいときだけ使う。

### 影

影は情報を持たせない。使うのは実質1種類だけ。

| 用途 | 値 |
|---|---|
| カード・パネルの浮き | `shadow-sm` ないし `shadow-[0_1px_4px_rgba(0,0,0,0.05)]` |
| 遅延行の左帯 | `shadow-[inset_3px_0_0_var(--color-late)]` |
| 入力欄のフォーカス | `shadow-[0_0_0_3px_var(--color-primary-lt)]` |

濃い影や大きなぼかしは使わない。面の重なりは影ではなく罫（`--border`）で表す。

### 罫

- `--border`（`#DCE4EF`）が既定。カードの外周、リストの区切り
- `--line`（`#B9C6D9`）は強調したいときと、「未設定」のようなプレースホルダー文字

## 5. 余白・レイアウト

- **サイドバー幅 260px。** `w-[260px]`（`layout/sidebar.tsx`）と、本文側の `lg:pl-[260px]`
  （`layout/app-shell.tsx`）が対になっている。片方だけ変えない
  （モックアップの `--sidebar-w: 240px` は古い値。実装が正）
- **モバイルの下部ナビ分の余白は `pb-14`。** 1024px 以上で `lg:pb-0` に戻す
- 余白は Tailwind の既定スケール（4px刻み）に従う。`p-7` / `px-6` / `py-6` あたりが
  カード内側の標準

レスポンシブのブレークポイントと各画面の崩し方は
[`common-ui.md`](./design/screens/common-ui.md) を参照。

### ページヘッダー

全画面が `components/layout/page-header.tsx` の `PageHeader` を使う。**独自のヘッダーを書かない。**

- **タイトル行の高さは 64px 固定**（`h-16`）。縦パディングではなく高さを直接指定しているのは、
  戻るボタンやアクションボタンの有無で高さが動かないようにするため。画面を行き来したときに
  ヘッダーの下端が上下すると、直下のコンテンツの開始位置が毎回ずれる
- 見出しは `font-serif text-[20px] font-bold tracking-[0.02em]`。画面ごとに変えない
- **ヘッダー内のアクションボタンは1種類。** `px-5 py-2.5 text-[13px]`（約40px）で揃える
- **付随要素はタイトル行の中に入れない。** 日付・タブなどは `children` に渡し、行の下に積む。
  行の高さを固定している以上、中に足すと収まらない

```
┌──────────────────────────────┐
│ 苦手問題                      │ ← タイトル行 64px 固定
├ - - - - - - - - - - - - - - -┤
│ [復習中 12] [克服済み 5]        │ ← children（画面ごと）
└──────────────────────────────┘
```

ログイン・新規登録は `AuthGate` がシェルの外で描画するため、この規格の対象外
（`components/auth/auth-card.tsx` が独自の見出しを持つ）。

## 6. アクセシビリティ

配色刷新の前提条件として置いた水準。ここを下回る変更はしない。

- **本文のコントラストは 4.5:1 以上**（WCAG AA）。上のトークン表の値がすべて実測値
- **色だけで意味を伝えない。** アイコンかテキストを必ず併記する
- **可視フォーカスリング。** `globals.css` の `*:focus-visible` が全要素に
  2px の `--primary` アウトライン（オフセット2px）を出す。個別に消さない
- **`prefers-reduced-motion` を尊重する。** `globals.css` でアニメーションを実質無効化済み
- アイコンのみのボタンには `aria-label` を必須とする

## 7. 実装との対応

- トークンは `@theme` で宣言してあるので、Tailwind のクラスとしてそのまま使える
  （`--color-primary` → `bg-primary` / `text-primary` / `border-primary`）
- **生の hex をコンポーネントに書かない。** 必要な色がトークンに無いなら、
  それは新しい意味を足そうとしているサインなので、まず §2 の4つの意味に照らす
- CSS の中で値が必要なときは `var(--color-primary-lt)` の形で参照する
  （`shadow-[0_0_0_3px_var(--color-primary-lt)]` がその例）

## 扱っていないもの

- **ダークモード** — 未対応。`globals.css` の `body` に背景色を直書きしており、
  `prefers-color-scheme` の記述もない。ink 面を持つぶん移行はしやすい
- **原因タグ6種の色分け** — 現状すべて同じ淡色で、傾向がスキャンできない。配色とは独立の課題
- **インタラクションの挙動**（トースト、確認ダイアログ、二重送信防止）と
  **レスポンシブの詳細** — [`common-ui.md`](./design/screens/common-ui.md) の担当
