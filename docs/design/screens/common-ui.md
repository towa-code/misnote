# 共通UI仕様

全画面に共通するUI/UXのルール。個別画面の記述より優先される。

---

## カラー・アクセシビリティ

色・文字・かたち・余白のルールは [デザインガイド](../../DESIGN.md) にまとめた。
トークンの実値は `frontend/src/app/globals.css` の `@theme` が正。

守るべき点だけ再掲する。

- 色の意味は4つに限る: 青＝未克服/行動、緑＝克服済み、金＝遅れ、赤＝間違い/エラー
- 遅れている項目は「地の色＋左3pxの帯＋バッジ」で示し、**問題文の色は変えない**。金地に白文字は載せない
- テキストと背景のコントラストは **4.5:1 以上**（WCAG AA）。色だけで意味を伝えず、アイコンまたはテキストを併記する（例: 間違い回数は「×」アイコン＋赤）
- すべてのインタラクティブ要素に可視フォーカスリング（`:focus-visible`、2px アウトライン）
- アイコンのみのボタンには `aria-label` を必須とする

---

## インタラクション

- クリック/タップ対象は最小 **32×32px**（モバイルでは 44×44px）。小さいアイコンはパディングで当たり判定を広げる
- ボタンは押下中 disabled にし、スピナーを表示（二重送信防止）。300ms を超えるロードにはスケルトンまたはスピナー
- 保存・登録成功時はトーストで通知（3〜5秒で自動消滅、`aria-live="polite"`）
- **削除は確認ダイアログを挟む**（科目・単元・問題）。紐づくデータがあり削除できない場合（409）は、理由と対処（「先に問題を移動または削除してください」）をダイアログ内に表示
- フォームエラーは対象フィールドの直下に赤字＋アイコンで表示し、最初のエラーフィールドにフォーカスを移す
- 次の復習日の日付ピッカーは `min` を今日に設定（過去日は選択不可）

## サイドバーの克服率バー

1024px 以上のサイドバー最下部に、克服の進みぐあいを常時表示する。「克服率」ラベル・進捗バー・「◯ 問克服 / 全 ◯ 問」の3行。

- **克服率 = mastered な間違いノート ÷ 間違いノート総数（active + mastered）。** 母数は「一度でも間違えた問題」で、登録しただけの問題は含まない
- 件数は [`GET /stats/summary`](../api/stats.md) から取る。**画面遷移のたびに取り直す** — サイドバーは一度しかマウントされないため、これがないと復習で克服してもバーが動かない
- 読み込み中と取得失敗時は**バーごと非表示**にする。先に 0% のバーを出すと「克服率0」に見えるうえ、補助表示のためにエラーを出す価値がない
- ノートが0件のアカウントは 0% のバーと「0 問克服 / 全 0 問」
- 1024px 未満ではサイドバーごと隠れる（下部ナビゲーションに置き場所がないため）。表示されないだけでリクエスト自体は走る

## レスポンシブ方針

ターゲット（小中高生）はスマートフォン利用が主と想定し、実装はモバイルファーストで行う。

| ブレークポイント | レイアウト |
|---------------|---------|
| 1024px 以上 | 左サイドバーナビゲーション（現行モックアップどおり） |
| 1024px 未満 | サイドバーを下部ナビゲーション（ホーム / 苦手問題 / 科目管理 の3項目、アイコン＋ラベル）に置き換え。「＋問題を登録」はヘッダー右上に維持 |
| 768px 未満 | 問題登録の2カラムレイアウトを1カラムに積む。苦手問題一覧のテーブルをカード型リストに切り替え |

- ブレークポイント: 375px（スマホ基準）/ 768px / 1024px / 1440px
- 本文フォントは 16px 以上（iOS の自動ズーム回避）、横スクロールは発生させない
- `prefers-reduced-motion` 時はアニメーションを無効化する

> 現行の HTML モックアップはデスクトップ（1280px）のリファレンス。モバイルレイアウトは上記方針に従って実装時に展開する。
