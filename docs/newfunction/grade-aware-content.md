# 機能案：学年に応じた最適化

> ⚠️ **エージェントへ：** この機能は構想段階です。ユーザーが明示的に実装を指示するまで実装しないでください。

**目的：** ユーザー情報として学年を持ち、学年に応じて画面の文言や提示内容を最適化する。misnote の対象は小学生から高校生までと幅が広く、同じ文言が小学生には難しく高校生には幼く感じられる。「何を書けばいいか分からず、ただ保存するだけ」を防ぐには、その学年に届く言葉である必要がある。

---

## 最適化したい箇所

効き目が大きい順。学年を持つこと自体が目的ではなく、以下が実現したいこと。

| # | 箇所 | 学年で何が変わるか | 効果 |
|---|---|---|---|
| 1 | 科目・単元プリセット | 提示する科目セット（中2に「物理基礎」を出さない） | ◎ |
| 2 | 原因タグのラベル | 「解き方が思いつかなかった」→ 小学生向けの言い換え | ○ |
| 3 | 入力欄のプレースホルダー・補助文 | 語彙と漢字の水準 | ○ |
| 4 | 空状態・初回オンボーディングの文言 | 語りかけのトーン | ○ |
| 5 | 復習間隔（`SUGGEST_INTERVALS`） | 学年ごとの既定値 | △ |

1 は [preset-subjects-units.md](./preset-subjects-units.md) と直結する。学年が分かればプリセットをそのまま絞り込めるので、文言最適化よりも体感差が大きい。この機能案の本命は 1 で、2〜4 が続くと考えている。

5 は経験則の上に経験則を重ねることになるため、当面は全学年固定を推す。

---

## 検討事項・トレードオフ

### 学年は毎年変わる

`users.grade` をそのまま持つと毎年ユーザーが更新しない限り古くなる。選択肢：

| 案 | 内容 | 評価 |
|---|---|---|
| A | `grade` を持ち、進級時期にアプリから更新を促す | 単純。ただし更新されないと静かに古くなる |
| B | 入学年度や生年月を持ち、学年を導出する | 常に正しい。飛び級・浪人・海外校などの例外に弱い |
| C | 学年ではなく「小学生 / 中学生 / 高校生」の3段階だけ持つ | 文言最適化にはこの粒度で十分。更新頻度も数年に一度で済む |

文言の出し分けだけが目的なら **C** で足りる。科目プリセット（箇所 1）まで踏み込むなら学年の解像度が要るので **A** か **B** になる。どこまでやるかを決めてから選ぶ。

### 文言の置き場所

現状、プレースホルダーや補助文は各コンポーネントに直書きされている。学年で分岐させる時点で全部引っ越すことになるので、文言が増える前に一箇所へ集約しておくと後が安い。`src/lib/reason-tags.ts` が日本語ラベルを一箇所に持つ既存の前例になる。

**これは学年機能を作らなくても単体で意味がある**ので、先に済ませておける。

### 科目プリセットのマスタデータ（CSV）は再構成しない

[`docs/data/preset_subjects_units.csv`](../data/preset_subjects_units.csv)（中学172行・高校85行）を学年対応にするかを検討した結論。**全面的な再構成は不要**で、中学に列を1本足すだけでよい。

| 対象 | 判断 | 理由 |
|---|---|---|
| 高校 | 学年を持たせない | 「数学Ⅰ / 数学Ⅱ」「物理基礎 / 物理」と科目自体が既に段階を表している。履修学年は学校・コースでバラバラなので、学年を割り当てても精度が出ない |
| 中学（数学・理科・社会） | 末尾に `grade` 列を追加 | 単元が学年配当どおりに並んでいる（正負の数〜データの活用＝中1、式の計算〜箱ひげ図＝中2、多項式〜標本調査＝中3）。列を足すだけで絞り込める |
| 中学（国語・英語） | `grade` は空欄のまま | 「漢字・語彙」「文法」「現代文読解」はどれも3年間通して出てくる。無理に学年を振ると嘘のデータになる |
| 小学 | **保留**（2026-08-05 時点の判断） | CSV に小学カテゴリは無い。学年最適化の効果は大きいが、まず中学・高校で形にしてから判断する |

`grade` は nullable な追加列なので、既存行に影響しない（末尾追加）。

なお、CSV には数学の「検定科目の分割版（数学Ⅰ/A/Ⅱ/B…）」と「受験セット版（数学ⅠA/ⅡBC）」が両方入っている。これは学年ではなく用途の軸なので、`grade` とは別軸として共存させる。

### 学年で絞るのは初期表示だけにする

学年で候補を絞り込んでも、**全学年を見られる導線は必ず残す**。misnote は間違えた問題を記録するアプリなので、高1が中3の因数分解でつまずいて記録する、という使い方が普通に起きる。学年で隠すとこのアプリ本来の用途を塞ぐ。

### 検証コストが学年の数だけ増える

文言を3段階に分けると、レビューも表示確認も3倍になる。段階は少なく保つ（3段階まで）。

### 学年は必須にしない

入力を必須にすると登録の入口が重くなり、「入口の軽さ」という差別化軸と衝突する。未入力を既定（＝現在の文言）として扱い、任意入力にする。

## API/DB 変更点（概略）

| 種別 | 変更 |
|------|------|
| DB | `users` に学年カラム（上記 A/B/C のいずれか）。nullable |
| API | `GET /v1/auth/me` のレスポンスに追加。アカウント画面から更新する `PUT` が要る |
| フロント | 文言テーブルを学年で引く。文言そのものはフロントだけが持つ（原因タグと同じ方針） |
